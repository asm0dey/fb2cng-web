Dark theme

Same markup — the palette is eight custom properties on :root, re-declared inside one @media (prefers-color-scheme: dark) block. No toggle, no JS, no stored preference: the phone decides at night, the desktop at its own schedule. Frames below show the four screens where the dark values actually matter; every other screen is the same substitution.

fb2 → epub — front-end spec

Every screen at 375px and 1440px. One stylesheet, one breakpoint at 640px, server-rendered markup: real <form> POSTs, <details> for collapse, htmx only for swapping the convert-card region.

Convert · idle

The default route. Three taps on a phone: file picker → pick → Convert. The dashed area is a <label for="file"> wrapping an <input type="file" multiple>, so it is a native tap target on iOS and a drop target on desktop (5 lines of JS: dragover/drop → assign files). Multi-select and dropping several files land in the same queue; one preset applies to the whole batch.

How presets work

A preset stores only the options you changed. Everything else comes from fb2cng’s built-in defaults at conversion time, so upgrading the binary picks up new defaults for free.

The default preset is preselected on the Convert screen — that is the only thing the marker does.

Deleting a preset does not touch already-converted files. Presets live in ~/.config/fb2web/presets/<name>.yaml; editing that file by hand is equivalent to using this screen.

Settings · preset editor

One <form> around ~100 rows; only rows whose value differs from the built-in default are submitted (server diffs against defaults, stores the diff). Search + "changed only" are the same 20 lines of JS: hide rows whose data-path doesn’t match, hide groups left empty, and rewrite each group’s match count. Changed rows carry an amber left rule and a dot after the label; the label itself is the reset link. Every row carries its default and a one-line description — on the phone as a second line, on desktop in the third column — so there is no tooltip or help modal anywhere.
